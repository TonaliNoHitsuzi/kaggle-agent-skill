# v2 增强需求（来自孵化仓主会话实战反馈 · 已定稿）

> 2026-10-16 边界测试轮（t2i-runner v4）期间讨论定稿；三项，均服务于"初学者领鸡蛋等待体验"

## 定稿三项

### V2-1 图级心跳（进度可见）

**问题**：commit run 期间 status 只有 RUNNING 一个词，等待期盲等；网页 /log 默认显示上一完成版本日志，易误判卡死。

**方案**：
- kernel 端：每张图完成打印机器可解析心跳行 `PROGRESS n/N [batch_tag]`（粒度=图级；单张 24s，步骤级无价值，细日志 Kaggle 原生 tqdm 已有）
- kwatch 端：等待期轮询展示最后已知进度 + 按公式估算剩余时间
- 网页 Active Events 轮询不做进通用层（依赖浏览器登录态，属重度用户私产）

### V2-2 预检三连 + dry-run 原则

**方案**：push 前依次执行——
1. **估时**：公开公式 `任务时长 ≈ 77s 模型加载 + N × 24.5s/张`（1024²/25步/T4 实测，写进文档供替换参数）
2. **查余额**：quota 查 GPU 周配额余量，不足或预估超余量则警告
3. **冒烟先行**：大任务必先冒烟（如 2 张全链路验证）再全量——教程级原则 + kwatch 可选 `--smoke` 参数（自动缩减 batch 到前 2 张跑一轮）

### V2-3 轻量任务标识 + 静默 job_id

**方案**：
- 结果拉取落时间戳目录（`out/YYYYMMDD-HHMM/`），report.json 自含全部任务配置
- kwatch push 时自动计算 `job_id = sha1(jobs 配置)[:8]`，静默注入：kernel 常量、report.json 首字段、目录名后缀（`out/YYYYMMDD-HHMM_ab12cd34/`）——全程自动，初学者零感知零新概念；上层服务（如本地流水线）可依赖它做任务对账与结果校验

## 讨论中撤销项（记录理由，防复活）

| 撤销项 | 理由 |
|--------|------|
| 任务台账 / 配置分离 / 自动归档 | 高频流水线私产需求，初学者单发任务无此病 |
| 失败自诊断 | 小 CLI 自己写清楚报错即可 |
| Gist 远程心跳 | 多一个故障点，收益不配 |
| 钩子机制（notify/post_fetch） | 初学者无可挂之物，砍 |
| 生图避坑进通用层 | 领域经验≠平台经验；平台坑 qa.md 已覆盖，生图坑留案例附录（bench-v4-report.md 人工验收节） |
| 多模型注册 / init 通道 / LoRA | 图像模型部署是上层服务，skill 只留案例 |
